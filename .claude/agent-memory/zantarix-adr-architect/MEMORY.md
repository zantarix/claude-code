# ADR Architect Memory — Zantarix Claude Code marketplace

Index of my persistent notes for authoring ADRs in this repo.

## Repo-specific notes

- This repo is a Claude Code plugin marketplace: entirely configuration and markdown, no build/test/compiled output. ADRs are decisions about plugin/skill/agent/rule design and orchestration, not code internals.
- Writes under `docs/adr/` are guarded: only the `zantarix:adr-architect` agent may edit them (guard-adr.sh hook).
- `format.sh` auto-runs markdownlint --fix on `.md` after each edit — no manual markdown formatting needed. It is deliberately a **formatter, not a linter** (Maddy-confirmed): always exits 0, swallows all lint errors and even a missing markdownlint binary. Unfixable defaults like MD025 (multi-`#` OKF indexes) and MD013 (long ADR lines) fire if run manually — these are expected house-style conflicts, never something to "fix" by restructuring bundle files.
- Same-project skill files (SKILL.md) may be cited in References via relative paths (from a theme dir: `../../../plugins/...`); the "no same-project references" rule applies only to ADRs, not skills.
- **This repo's ADR library is an OKF bundle** (migrated 2026-07-24 via `/okf-migrate-adr`, per ADR-0002). Operate in OKF mode: four-digit numbering (next is 0004), themes `orchestration/` and `knowledge/`, canonical index `docs/adr/index.md` + history `docs/adr/log.md`, maintained via `/okf-curate`. No README table, no inventory.md. Bundle link convention is **relative** links (not bundle-root-absolute), matching ADR-0002's cross-theme `../<theme>/NNNN-*.md` rule.
- **The whole OKF house style — ADRs included — migrated to v0.2 canonical** (ADR-0003, Accepted 2026-07-31; ADR-0002 carries a forward erratum to it). v0.2: `generated:{by,at}` replaces `timestamp`; `sources` frontmatter + keyed footnote attribution replaces body `# Citations`; `verified`/`status`(draft|stable|deprecated)/`stale_after` available where meaningful; `okf-init` scaffolds new bundles at `okf_version:"0.2"`. ADRs follow the general v0.2 style with exactly TWO divergences: (1) ADRs keep the mid-document `## References` body section instead of `sources`/footnotes — the sole structural carve-out, Maddy-confirmed twice; (2) ADR frontmatter `status` keeps the ADR vocabulary (Proposed/Accepted/Deprecated/Superceded), NOT OKF's `draft|stable|deprecated` (semantic distinction, not a freeze). ADRs use `generated` too — `timestamp` is retired. ADRs seldom carry `verified`/`stale_after` (acceptance = `status`, obsolescence = supersession) but nothing freezes them out. Rule: **writes bring a concept to full v0.2 compliance** — any new/edited concept is written fresh-today in full v0.2; untouched content is never bulk-rewritten (v0.2 consumers fall back to `timestamp`/`# Citations`), so bundles converge gradually. The `docs/adr` bundle marker is now `okf_version:"0.2"`. `Attested Computation` type exists upstream but no Zantarix tooling uses it. Zantarix agent-actor convention for `generated.by`: `<agent-name>/<model-id>` (this ADR used `adr-architect/claude-opus-4-8`), per spec §7 `<producer>/<version>` — the colon-prefix form is reserved for `human:`/`process:`.
- ADR numbering is globally sequential across themes; it started at 001 in legacy mode (unlike sibling `cursus`, whose 000 was a founding-constraints ADR) and was re-padded to 0001+ in the migration.
