## Repo-specific notes

- This repo is a Claude Code plugin marketplace: entirely configuration and markdown, no build/test/compiled output. ADRs are decisions about plugin/skill/agent/rule design and orchestration, not code internals.
- Writes under `docs/adr/` and `docs/architecture/` are guarded: only the `zantarix:architecture-curator` agent may edit them (guard-adr.sh hook).
- **ADR-0004 (Accepted 2026-08-06, ratified by `human:mscharley`) established the architecture regime** — immutable ADRs + living Overview/Specification/Constraint Ledger concepts in `docs/architecture` bundles, materiality gate (`zantarix:materiality-gate`, preloaded), human-only `/accept-adr` writing `verified:{by: human:<forge-username>}` (Accepted = ratified direction, NOT implemented), plugin `architecture-reviewer` with mandated pre-acceptance ADR review (rules/zantarix/architecture-review.md), adoption via human-run `/adopt-architecture`. Tooling implemented 2026-08-06. ADR-0004 admits no ledger entry (it creates the ledger and forecloses nothing) — the entry test is **foreclosure**, not what a decision is about; "commitment" and the constraint-admission/topology binary are retired vocabulary (see `zantarix:architecture-vocabulary`). Acceptance errata rule confirmed: a pure agent **rename** (adr-architect→architecture-curator) is NOT functional incorrectness → no errata; `generated.by: adr-architect/*` on old concepts is a correct historical author record left as a pre-regime era marker, never chased with errata or bumped at acceptance.
- `format.sh` auto-runs markdownlint --fix on `.md` after each edit — no manual markdown formatting needed. It is deliberately a **formatter, not a linter**: always exits 0, swallows all lint errors and even a missing markdownlint binary. Unfixable defaults like MD025 (multi-`#` OKF indexes) and MD013 (long ADR lines) fire if run manually — these are expected house-style conflicts, never something to "fix" by restructuring bundle files.
- Same-project skill files (SKILL.md) may be cited in References via relative paths (from a theme dir: `../../../plugins/...`); the "no same-project references" rule applies only to ADRs, not skills.
- **This repo ADOPTED the architecture-documentation regime on 2026-08-06** (via human-run `/adopt-architecture`, while ADR-0004 was still Proposed). Operate in **regime mode** (superset of OKF): bundle moved `docs/adr` → **`docs/architecture`**, root singleton `constraints.md` (type `Constraint Ledger`) is the regime marker + machine-readable index. Four-digit numbering (next is 0009), themes `orchestration/`, `knowledge/`, `components/` — each now has an `overview.md` (grown on demand; ADR-0004 rejected mandatory overviews). Canonical index `docs/architecture/index.md` (targeted: ledger + themes + a `# Specifications` section for cross-cutting specs, no per-ADR roll-call) + history `docs/architecture/log.md`, maintained via `/okf-curate`. No README table, no inventory.md. Link convention is **relative**. Ledger holds two entries (OKF knowledge-format constraint from ADR-0002/0003; interactive ratification from ADR-0006); ADR-0001/0004/0005 foreclose nothing, so no entries. My `generated.by` actor is now `architecture-curator/<model>`. A Specification whose subject spans themes lives at the **bundle root**, not inside a theme (`ticket-workflow.md`, moved there 2026-08-13) — a local record only, deliberately NOT promoted into `architecture-vocabulary`/`okf-guide` as a general convention.
- **The whole OKF house style — ADRs included — migrated to v0.2 canonical** (ADR-0003, Accepted 2026-07-31; ADR-0002 carries a forward erratum to it). v0.2: `generated:{by,at}` replaces `timestamp`; `sources` frontmatter + keyed footnote attribution replaces body `# Citations`; `verified`/`status`(draft|stable|deprecated)/`stale_after` available where meaningful; `okf-init` scaffolds new bundles at `okf_version:"0.2"`. ADRs follow the general v0.2 style with exactly TWO divergences: (1) ADRs keep the mid-document `## References` body section instead of `sources`/footnotes — the sole structural carve-out, confirmed twice; (2) ADR frontmatter `status` keeps the ADR vocabulary (Proposed/Accepted/Deprecated/Superceded), NOT OKF's `draft|stable|deprecated` (semantic distinction, not a freeze). ADRs use `generated` too — `timestamp` is retired. ADRs seldom carry `verified`/`stale_after` (acceptance = `status`, obsolescence = supersession) but nothing freezes them out. Rule: **writes bring a concept to full v0.2 compliance** — any new/edited concept is written fresh-today in full v0.2; untouched content is never bulk-rewritten (v0.2 consumers fall back to `timestamp`/`# Citations`), so bundles converge gradually. The `docs/architecture` bundle marker is `okf_version:"0.2"`. `Attested Computation` type exists upstream but no Zantarix tooling uses it. Zantarix agent-actor convention for `generated.by`: `<agent-name>/<model-id>` (this ADR used `adr-architect/claude-opus-4-8`), per spec §7 `<producer>/<version>` — the colon-prefix form is reserved for `human:`/`process:`.
- **Errata are ordered chronologically, oldest first (append to the bottom)** — no prompt states this; it is settled by the sibling `cursus` corpus, where every multi-erratum ADR reads oldest→newest. Not reverse-chronological like `log.md`.
- ADR numbering is globally sequential across themes; it started at 001 in legacy mode (unlike sibling `cursus`, whose 000 was a founding-constraints ADR) and was re-padded to 0001+ in the migration.
