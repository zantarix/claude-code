"Work item" is the umbrella term for anything GitLab tracks. The backend entity is called `WorkItem`. Each work item has a type. The most common type is `Issue`. The other types are `Task`, `Epic`, `Objective`, and custom types. `Issue` is one work-item *type*. It is not the legacy REST `/issues` resource.

When you act on any work item, regardless of type, default to the work-item APIs and MCP tools: `get_workitem_notes`, `workItemUpdate`, `workItemCreate`, `workItemAddLinkedItems`. Use the legacy `/issues` endpoints only when the work-item API does not expose what you need. Those endpoints are read-mostly. They miss widget data for status, hierarchy, linked items, and custom fields.
